# Prediction workspace

`workspace.html` is the18th allowlisted public page and appears in shared
navigation. It uses the existing dependency-free renderer/API client and CSP;
there is no inline script, probability heuristic, auto collector or live feed.
Static builds include the same page. Public/default configuration shows an
unavailable local experimental workspace, not demo probabilities.

For explicit local shadow review, run the Flask application on the same local
origin using FORECAST_API.md, then open
`workspace.html?id=match:manual:<existing-session-id>`. Existing replay session
identifiers work as declared by the collector. Entering an ID does not create or
collect a session. Source writes remain the separate local CLI workflow. No hosted
authentication, cloud notes or background live polling is introduced.

Each refresh requests one versioned forecast/state response, then bounded issued
history when a source core exists. The API client only coalesces in-flight reads;
it does not retain completed predictions. Manual/replay mode, source state, source
age **at refresh**, unknown event lag, source cutoff/revision, state/model IDs,
calibration date, available model sample counts, prior-history scope and excluded
context families are visible. There is no unqualified live badge.

A current shadow forecast links to its actual issued history element. Expand that
native details element for the complete joint distribution, unknown mass, target,
feature hash, model/dataset/state identity and replacement link. Historical entries
remain labelled past entries. OTHER is not assigned zero runs or zero wicket risk.
No exact marginal, confidence verdict or tactical recommendation is invented.

Source freshness is checked server-side; the UI also expires its current link
after the returned remaining confirmation window, subtracting time spent loading
history. Expiry requires a user refresh and sends no extra request. An actual ball
can start before its next observation; see the prospective timing limitation in
FORECAST_API.md. Corrections/reconnects require a fresh confirmed snapshot. Stale,
paused, missing, disabled and ended states show no current forecast while retaining
available issued history. Network failures show a keyboard-accessible retry;
history failure is distinguished from a returned current ledger entry.

Forms have labels, loading/error/status announcements use existing accessible
components, details/anchors are native keyboard controls, long IDs wrap and tables
scroll. Reduced motion follows shared CSS. Browser evidence uses authored scores
and a clearly fictional portable model through the actual local API. It covers
375/1440 widths, mode labels, issued anchors, correction history, stale/error/retry,
delayed response, keyboard/reduced-motion, disabled mode and the actual15-second
UI expiry without polling. It is not real coach feedback or an external feed trial.

See `audit/workspace-ui-2026-10-28.json` and the separate18page/five-width
`audit/application-ui-t028-2026-10-28.json` report. Chrome only; screen-reader speech,
other browsers and hosted latency remain unverified. No deployment accompanied
these changes. Disable the experimental backend to return all workspaces to
unavailable while retaining source and issued ledgers.
